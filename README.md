# Боты «Маршрут построен»

Один Python-сервис обслуживает Telegram и MAX без Docker. Заявки и публичный контент хранятся на основном сайте; локальная SQLite содержит состояния диалогов, администраторов бота, настройки ответов, аудит и очередь доставки.

## Возможности

Пользователям доступны пошаговая заявка с согласием и проверкой данных, «Мои заявки», статусы, дополнения и отмена новой заявки, переписка с командой, выбор города, каталоги героев/бизнесов/интервью/статей/роликов и удаление персональных данных.

Администраторам доступны уведомления, списки и поиск заявок, ответственные, статусы, внутренние комментарии, переписка, напоминания, блокировка спама, история, ежедневная сводка, подтверждаемая рассылка публикаций и CSV-выгрузка. Владелец прямо в боте создаёт одноразовые приглашения, меняет роли, отключает доступ, связывает Telegram и MAX одного администратора, смотрит аудит и состояние системы.

Встроенный редактор открывается по пути «Панель администратора → Тексты, кнопки и изображения». В нём владелец или администратор может:

- изменить любой зарегистрированный ответ бота и вернуть исходный текст;
- добавить к ответу до 10 изображений по прямым HTTPS-ссылкам;
- переименовать или скрыть любую кнопку;
- отключить пользовательский раздел целиком, включая кнопки из уже отправленных сообщений;
- создать дополнительную кнопку и отдельное сообщение, которое она открывает.

Для динамических ответов маркер `{default}` оставляет внутри новой редакции актуальный встроенный текст с именами, номерами заявок, статусами и другими изменяемыми данными. Основные ответы присутствуют в редакторе сразу после запуска, редкие технические ответы автоматически появляются после первого показа. Редактор и пользовательские сообщения также доступны в Telegram и MAX.

Ручная рассылка публикации отправляется всем активным пользователям только после предпросмотра и явного подтверждения администратора. Автоматическая рассылка при публикации материала отключена.

## Требования

- Python 3.12+
- публичный HTTPS-домен для webhook;
- доступ к HTTPS API сайта;
- Telegram bot token;
- токен прошедшего модерацию бота MAX;
- системный сертификат доверия, необходимый для доступа к актуальному API MAX.

## Установка на VPS

```bash
sudo useradd --system --home /opt/marsrut-bot --shell /usr/sbin/nologin marsrut-bot
sudo mkdir -p /opt/marsrut-bot/{data,logs,backups}
sudo chown -R marsrut-bot:marsrut-bot /opt/marsrut-bot
cd /opt/marsrut-bot
python3.12 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env
```

Сгенерировать секреты можно командой `openssl rand -hex 32`. Значения `BOT_API_KEY_ID` и `BOT_API_SECRET` должны совпадать на VPS бота и на сервере сайта.

После заполнения `.env`:

```bash
.venv/bin/python -m scripts.register_webhooks
sudo cp systemd/marsrut-bot.service /etc/systemd/system/
sudo cp systemd/marsrut-bot-backup.service /etc/systemd/system/
sudo cp systemd/marsrut-bot-backup.timer /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now marsrut-bot.service marsrut-bot-backup.timer
```

Перед регистрацией webhook настройте HTTPS-прокси. Пример для Nginx находится в `deploy/nginx.conf.example`. Приложение слушает только `127.0.0.1:8080`.

## Первый владелец

Идентификаторы первых владельцев указываются в `TELEGRAM_OWNER_IDS` и `MAX_OWNER_IDS`. После первого запуска владельцы добавляют остальных через меню:

```text
Панель администратора → Администраторы → Добавить
```

Приглашение одноразовое и действует 30 минут. После создания владельцев значения из `.env` остаются аварийным способом восстановления доступа.

## Подготовка сайта

В `guessboss` добавлены миграция и API `/api/integrations/bot/*`. На сервере сайта задайте:

```dotenv
BOT_API_KEY_ID=marsrut-bot-v1
BOT_API_SECRET=<тот же секрет, что на VPS бота>
```

Затем примените Prisma migration обычным production-процессом проекта. Старые переменные `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` на сайте лучше очистить после запуска нового сервиса, иначе уведомления Telegram могут дублироваться.

## Проверка

```bash
.venv/bin/python -m pytest -q
.venv/bin/python -m ruff check app scripts tests run.py
curl https://bot.example.ru/health
systemctl status marsrut-bot
journalctl -u marsrut-bot -f
```

Расширенная диагностика защищена заголовком `X-Health-Token`, значение которого равно `APP_SECRET`:

```bash
curl -H "X-Health-Token: $APP_SECRET" https://bot.example.ru/health/details
```

## CI/CD

GitHub Actions автоматически запускает Ruff и тесты на Python 3.12 и 3.14 для каждого push и
pull request. Успешный CI после push в `main` автоматически запускает production-деплой: создаёт
резервные копии, обновляет только `marsrut-bot.service`, проверяет health-check и возвращает
предыдущий код при ошибке. Ручной запуск оставлен как аварийный вариант. Настройка описана в
[`.github/DEPLOYMENT.md`](.github/DEPLOYMENT.md).

Telegram при запуске приложения автоматически получает системную кнопку **Menu** с командой
`/start — Перейти к главной`. Каждый ответ бота также содержит понятный путь в главное меню;
команды `/start`, `/menu` и `/cancel` остаются доступны вручную.

## Резервные копии

Timer ежедневно делает согласованную SQLite-копию в `/opt/marsrut-bot/backups`. Резервные копии старше требуемого срока следует удалять существующей политикой хранения VPS. Ручной запуск:

```bash
.venv/bin/python -m scripts.backup
```

## Безопасность

- webhook Telegram и MAX проверяются отдельными секретами;
- запросы к сайту подписаны HMAC-SHA256 с timestamp и хешем тела;
- повторные webhook и отправки дедуплицируются;
- токены не пишутся в лог;
- персональные данные не дублируются в SQLite;
- выгрузка CSV доступна только владельцу или администратору;
- последнего владельца нельзя отключить или понизить;
- systemd unit ограничивает доступ процесса к файловой системе.
